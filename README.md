# Agentic Quant Research System

An AI-native system for quantitative research, built around explicit state management, deterministic computation, and agent-driven reasoning.

---

## Overview

Quantitative research combines two very different types of work.

Some tasks require open-ended reasoning:

* Interpreting research questions
* Designing experiments
* Diagnosing strategy behavior
* Proposing follow-up investigations

Other tasks require strict computational correctness:

* Loading historical data
* Constructing factors
* Running backtests
* Calculating performance metrics

This project explores how these responsibilities can be separated and coordinated within a single agent system.

The system uses LLMs for planning, analysis, and report generation, while all financial computations are executed through deterministic Python tools.

The focus is on agent architecture rather than trading performance.

## Research Context

The workflow is coordinated through a shared state object.

```python
ResearchContext
├── user_request
├── task_plan
├── market_data
├── factors
├── backtest_results
├── performance_metrics
├── diagnosis
├── experiment_suggestions
└── report
```

The context serves as the system's working memory and provides a transparent record of how a research report was produced.

## Architectural Decisions

### Explicit State over Hidden Conversation History

The system stores intermediate results in a typed state object rather than relying on chat history.

This makes workflows easier to inspect, debug, reproduce, and extend.

---

### Deterministic Tools over Generated Computation

Financial computations are never generated by the language model.

Instead, the model interacts with predefined tools that perform:

* Data loading
* Factor construction
* Backtesting
* Metric calculation

This ensures that numerical results remain reproducible and independently testable.

---

### Structured Outputs over Free-Form Text

Reasoning nodes communicate through structured objects.

For example, the planner produces a validated `TaskPlan` rather than free-form instructions.

This creates clear interfaces between reasoning and execution layers.

---

### Reflection over Single-Pass Generation

The system treats research as an iterative process.

After a backtest completes, an analysis agent reviews the results and produces observations about:

* Strategy robustness
* Potential overfitting
* Cost sensitivity
* Parameter stability
* Suggested follow-up experiments

The objective is not only to generate results, but also to critique them.

---

## Quantitative Research Constraints

The system is designed around several constraints that commonly appear in quantitative research.

### Reproducibility

Research outputs should be reproducible from the same inputs and configuration.

### Auditability

Every report should be traceable back to the data, factors, and experiments that produced it.

### Backtest Integrity

Research workflows should avoid introducing invalid assumptions into simulations.

Examples include:

* Look-ahead bias
* Data leakage
* Unrealistic execution assumptions

### Separation of Reasoning and Computation

The system explicitly separates:

```text
Reasoning
    ↓
Planning
Analysis
Diagnosis
Reporting

Computation
    ↓
Data
Factors
Backtests
Metrics
```

This separation forms the foundation of the architecture.
